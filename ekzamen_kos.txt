    Обеспечьте динамическую маршрутизацию на маршрутизаторах HQ-RTR и BR-RTR
    и межсетевом экране BR-FW:
    сети одного офиса должны быть доступны из другого офиса и наоборот.
    Разрешите выбранный протокол только на интерфейсах туннеля.
    Используйте OSPF для маршрутизации.
    Маршрутизаторы должны делиться маршрутами только друг с другом.
    Используйте аутентификацию в OSPF.
    В качестве пароля используйте P@ssword.
    Пароль должен передаваться с использованием хешированного ключа MD5.
    
    OSPF только на туннеле (и стыке с BR-FW), обмен маршрутами только между
    роутерами, аутентификация MD5, ключ P@ssword. Реализация «только друг с другом» —
    через passive-interface default + точечное no passive-interface.
    
    HQ-RTR:
        configure terminal
        router ospf 1
        ospf router-id 10.10.10.1
        passive-interface default
        no passive-interface tunnel.0
        network 10.10.100.0/27 area 0
        network 10.10.200.0/28 area 0
        network 10.10.30.0/29 area 0
        network 10.10.10.0/30 area 0
        exit
        interface tunnel.0
        ip ospf authentication message-digest
        ip ospf message-digest-key 1 md5 P@ssword
        exit
        exit
        write memory
        
    BR-RTR (стыки: tunnel.0 к HQ, fw к BR-FW в сети 10.20.10.0/30):
        configure terminal
        router ospf 1
        ospf router-id 10.10.10.2
        passive-interface default
        no passive-interface tunnel.0
        no passive-interface fw
        network 10.10.10.0/30 area 0
        network 10.20.10.0/30 area 0
        exit
        interface tunnel.0
        ip ospf authentication message-digest
        ip ospf message-digest-key 1 md5 P@ssword
        exit
        interface fw
        ip ospf authentication message-digest
        ip ospf message-digest-key 1 md5 P@ssword
        exit
        exit
        write memory
        
    BR-FW (Ideco), веб-интерфейс  Маршрутизация → OSPF:
        включить OSPF; задать аутентификацию соседей MD5, ключ P@ssword;
        добавить локальный интерфейс в сторону BR-RTR (сеть 10.20.10.0/30, area 0);
        анонсировать локальные сети 10.20.20.0/28 и 10.20.30.0/29 (area 0);
        убедиться, что OSPF активен только на интерфейсе к BR-RTR (не на LAN).

    Основной DNS-сервер реализован на HQ-SRV.
    Сервер должен обеспечивать разрешение имён в сетевые адреса устройств и обратно в соответствии с таблицей 3.

    Прямое и обратное разрешение по таблице, форвардер на публичный DNS (77.88.8.7/77.88.8.3).
    
    Установка:
        apt-get update
        apt-get install bind
        
    редактирование конфигурационного файла /var/lib/bind/etc/options.conf:
        listen-on { 127.0.0.1; 10.10.100.2; };
        listen-on-v6 { none; };
        forwarders {77.88.8.8; }; (либо вузовский 94.232.137.94)
        allow-query { any; };
        recursion yes; (не факт, что нужно)
        
    vim /var/lib/bind/etc/rfc1912.conf
        zone "au-team.irpo" {
            type master;
            file "au-team.irpo";
        };
        zone "10.in-addr.arpa" {
            type master;
            file "10.in-addr.arpa";
        };
        
    файлы зон создаются копированием шаблона:
        cd /var/lib/bind/etc/zone/
        cp empty au-team.irpo
        cp empty 10.in-addr.arpa
        
    Необходимо сконфигурировать файл au-team.irpo, который является прямой зоной, следующим образом:
        vim au-team.irpo
        $TTL 1D
        @ IN SOA hq-srv.au-team.irpo. root.au-team.irpo. (
            2026061701 ; serial
            12H ; refresh
            1H ; retry
            1W ; expire
            1H) ; minimum
            
        @ IN NS hq-srv.au-team.irpo.
        hq-srv IN A 10.10.100.2
        hq-cli IN A 10.10.200.2
        hq-rtr IN A 10.10.100.1
        hq-rtr IN A 10.10.200.1
        hq-rtr IN A 10.10.30.1 --(влан 999)
        br-rtr IN A 10.20.10.1
        br-fw IN A 10.20.10.2
        br-srv IN A 10.20.20.2
        br-cli IN A 10.20.30.2
        docker IN A 172.16.1.1
        web IN A 172.16.2.1
        
    Обратная зона 10.in-addr.arpa (восстановленная структура таблицы):
        $TTL 1D
        @ IN SOA hq-srv.au-team.irpo. root.au-team.irpo. (
            2026061701 ; serial
            12H ; refresh
            1H ; retry
            1W ; expire
            1H ) ; ncache
            
        @ IN NS hq-srv.au-team.irpo.

НАСТРОЙКА ФАЕРВОЛЛА

    Перейдите в веб-интерфейс Ideco NGFW (IDC-FW) в раздел «Сетевые интерфейсы» и
    настройте три интерфейса согласно новой топологии.
    
    WAN интерфейс (Внешний):
        Выберите интерфейс, который смотрит в сторону Ek Router (например, eth0 или vmbr0).
        Режим: Статический ІР.
        ІР-адрес: 10.20.10.2.
        Маска подсети: 255.255.255.0 (или /24).
        Шлюз по умолчанию: 10.20.10.1 (это ІР-адрес Ek Router).
        DNS-серверы: Укажите работающие DNS. Можно использовать 8.8.8.8 и 94.232.137.104 (вузовский) для резерва.
        Нажмите «Сохранить».
        
    LAN интерфейс (Внутренний для клиентов):
        Выберите интерфейс для локальной сети (например, eth1 или vmbr1).
        Режим: Статический ІР.
        ІР-адрес: 10.20.20.1.
        Маска подсети: 255.255.255.0 (/24).
        Нажмите «Сохранить».
        
    DMZ интерфейс (Внутренний для серверов):
        Выберите интерфейс для демилитаризованной зоны (например, eth2 или vmbr2).
        Режим: Статический ІР.
        ІР-адрес: 10.20.30.1.
        Маска подсети: 255.255.255.0 (/24).
        Нажмите «Сохранить».
        
    Настройка правил файрвола (FORWARD)
        Чтобы клиенты из LAN и DMZ могли выходить в интернет через WAN, необходимо
        разрешить прохождение трафика между этими зонами. Перейдите в раздел
        «Правила трафика» -> «Файрвол» -> вкладка «FORWARD».
        
        Создайте правило для LAN:
            Нажмите «Добавить».
            Действие: Разрешить.
            Источник: Выберите зону LAN (или укажите сеть 10.20.20.0/24).
            Назначение: Выберите зону WAN (или укажите любой адрес, Any).
            Нажмите «Сохранить».
            
        Создайте правило для DMZ:
            Нажмите «Добавить».
            Действие: Разрешить.
            Источник: Выберите зону DMZ (или укажите сеть 10.20.30.0/24).
            Назначение: Выберите зону WAN.
            Нажмите «Сохранить».
            
    Настройка SNAT (Source Network Address Translation)
        Перейдите в раздел «Правила трафика» -> «Файрвол» -> вкладка «SNAT».
        Нажмите «Добавить».
        Действие: SNAT (или Маскарадинг).
        Источник: Выберите обе зоны LAN и DMZ (удерживайте Ctrl для выбора
        нескольких). Либо укажите диапазон сетей 10.20.20.0/24 и 10.20.30.0/24.
        Назначение: WAN (или любой адрес).
        Тип трансляции: Выберите «Маскарадинг» (это автоматически подставит ІР вашего
        WAN-интерфейса).
        Нажмите «Сохранить».
        
    Настройка DNS на клиентах
        Чтобы клиенты могли разрешать доменные имена в IP-адреса, на них нужно прописать
        DNS-сервера.
        На клиентах (IDC-ADMIN, IDC-DC):
        В настройках сети укажите DNS-серверы, например, 8.8.8.8 и 94.232.137.104.
        Если клиенты получают ІР-адреса по DHCPР от файрволла, то DNS нужно указать в
        настройках DHCP-сервера на IDC-FW. Так как по условию у нас статика, просто
        пропишите DNS вручную на самих клиентских машинах.
        
        Или можно прописать DNS глобально на самом файрволле IDC-FW, и тогда он будет
        выступать в роли DNS-ретранслятора (forwarder). Для этого в разделе «Управление
        сервером» -> «Настройки» укажите те же DNS (8.8.8.8, 94.232.137.104), а на клиентах в
        качестве DNS-сервера укажите ІР-адрес самого файрволла (10.20.20.1 для LAN и
        10.20.30.1 для DMZ).
        
        Зайдите в веб-интерфейс файрволла, в раздел «Диагностика» -> «Ping».
        Попробуйте пропинговать внешний ІР-адрес, например, 8.8.8.8.
        Попробуйте пропинговать доменное имя, например, yandex.ru.
